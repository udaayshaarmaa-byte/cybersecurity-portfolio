# Logs, Log Management & Log Formats
---

## 1. Why Logs Matter

**Log** = a record of events that occur within an organization's systems.

Like history books, receipts, and diaries, logs **preserve event details**. In security, those details support investigations by answering the **5 W's**:

| Question | Detail captured |
|---|---|
| **Who** | The user or system that triggered the event |
| **What** | The action that took place |
| **When** | Timestamp of the event |
| **Where** | Location  host, IP address, system |
| **Why** | Reason/context for the event |

Originally logs were used purely for **troubleshooting** (e.g. error logs revealing root cause of a fault). Today, virtually all devices generate logs that provide value far beyond troubleshooting  primarily **security monitoring**.

> {Logs let analysts build a story and timeline around event occurrences  this reconstruction is the foundation of incident investigation.}

---

## 2. Log Analysis

**Log analysis** = the process of examining logs to identify events of interest.

- Security teams access logs via **logging receivers** like SIEM tools, which **consolidate** logs into a central repository.
- SIEM tools perform three key functions:

| Step | What happens |
|---|---|
| **Collect** | Data gathered from multiple sources |
| **Aggregate / Centralize** | Logs combined into one place |
| **Normalize** | Diverse log formats converted into a single preferred format |

- **Log forwarders** = software that automatically collects logs from sources and forwards them to a centralized log repository.

## 3. Types of Logs

| Log type | Generated by | Example |
|---|---|---|
| **Network** | Firewalls, routers, switches, proxies | Connection allow/deny entries |
| **System** | Operating systems (Windows, Linux, macOS, Chrome OS) | OS-level events |
| **Application** | Software applications | App-specific event records |
| **Security** | Antivirus, IDS/IPS | File deletion, malware detection |
| **Authentication** | Any login/auth event | Successful or failed login attempts |

### Example  Authentication log
```
Login Event [05:45:15] User1 Authenticated successfully
```

### Example  Verbose authentication log
**Verbose logging** = records additional, detailed information beyond the default.
```
Login Event [2022/11/16 05:45:15.892673] auth_performer.cc:470 User1 Authenticated successfully from device1 (192.168.1.2)
```

### Example  Network log (router)
A router log entry might show:
- **Action**: ALLOW
- **Source**: an IP address
- **Destination**: e.g. google.com
- **Timestamp**: exact date/time of the action

> {The timestamp is one of the most essential fields  it's what allows analysts to correlate multiple events into a timeline.}

## 4. Log Management

**Log management** = the process of collecting, storing, analysing, and disposing of log data.

### What to log
- Choose log sources most likely to contain useful information for your events of interest.
- Reduce excessive verbosity where it isn't needed.
- **PII** (phone numbers, emails, names, etc.) requires special handling  and in some jurisdictions may not be loggable at all.

### The problem with overlogging
Logging everything is the **most common mistake** organizations make. Consequences include:
- Increased storage and maintenance costs
- Increased system load → performance/usability issues
- Harder to search for and identify important events

### Log retention
Some industries have **regulatory requirements** dictating how long logs must be kept:

| Sector | Regulation |
|---|---|
| Public sector | FISMA (Federal Information Security Modernization Act) |
| Healthcare | HIPAA (Health Insurance Portability and Accountability Act) |
| Financial services | PCI DSS, GLBA, SOX |

### Log protection
- Malicious actors often **modify logs** to mislead investigators and hide their activity.
- **Centralized log servers** maintain log integrity  logs are sent off the local machine to a dedicated server, creating a barrier between attacker and log data.

> {If logs only live on the compromised host, an attacker who gets admin rights can simply edit the evidence. Centralization is what keeps logs trustworthy.}

## 5. Common Log Formats

There is **no single standard** log format  analysts must be comfortable interpreting several.

### JSON (JavaScript Object Notation)
- Lightweight, human-readable, used heavily in web tech and cloud environments.
- Syntax elements:

| Element | Purpose |
|---|---|
| **Key-value pair** | Links a key to its value, e.g. `"Alert": "Malware"` |
| **Comma** | Separates data items |
| **Double quotes** | Enclose string (text) values; numbers are unquoted |
| **Curly brackets `{ }`** | Enclose an **object**  a comma-separated list of key-value pairs |
| **Square brackets `[ ]`** | Enclose an **array**  an ordered, comma-separated list |

Example object:
```json
"User":
{
    "id": "1234",
    "name": "user",
    "role": "engineer"
}
```

---

### Syslog
**Syslog** refers to three related things:

| Aspect | Description |
|---|---|
| **Protocol** | Transports logs to a centralized server; port **514** (plaintext) / **6514** (encrypted) |
| **Service** | Log-forwarding service  consolidates logs from multiple sources into one location |
| **Log format** | Native Unix logging format; consists of **header + structured-data + message** |

Example entry:
```
<236>1 2022-03-21T01:11:11.003Z virtual.machine.com evntslog - ID01 [user@32473 iut="1" eventSource="Application" eventID="9999"] This is a log entry!
```

Breakdown:

| Component | Value | Notes |
|---|---|---|
| **Priority (PRI)** | `<236>` | Urgency of event  generally, lower = more urgent |
| **Timestamp** | `2022-03-21T01:11:11.003Z` | `T` separates date/time; `Z` = UTC |
| **Hostname** | `virtual.machine.com` | Machine that sent the log |
| **Application** | `evntslog` | Source application |
| **Message ID** | `ID01` | Identifier for the message |
| **Structured-data** | `[user@32473 iut="1" eventSource="Application" eventID="9999"]` | Additional key-value info in brackets |
| **Message** | `This is a log entry!` | Detailed description of the event |

> Note: Syslog headers can be combined with JSON or XML formats, and custom formats also exist.

---

### XML (eXtensible Markup Language)
- Native file format used in **Windows** systems.
- Uses **tags**, **elements**, and **attributes** instead of key-value pairs.

| Term | Description |
|---|---|
| **Tag** | Pair of start `<tag>` and end `</tag>` markers enclosing data |
| **Element** | Tag + the data it contains; every XML doc needs one **root element** containing **child elements** |
| **Attribute** | Extra info inside a tag, always quoted, e.g. `Name='SubjectUserSid'` |

Example:
```xml
<Event>
    <EventID>4688</EventID>
    <Version>5</Version>
</Event>
```
`<Event>` is the root element; `<EventID>` and `<Version>` are child elements.

Example with attributes:
```xml
<EventData>
    <Data Name='SubjectUserSid'>S-2-3-11-160321</Data>
    <Data Name='SubjectUserName'>JSMITH</Data>
</EventData>
```

---

### CSV (Comma Separated Value)
- Data values separated by commas; **position** of each value corresponds to a field, but field **names may not be included** in the log itself.
- It's critical to know what fields the source device (IPS, firewall, scanner, etc.) includes.

Example:
```
2009-11-24T21:27:09.534255,ALERT,192.168.2.7,1041,x.x.250.50,80,TCP,ALLOWED,1:2001999:9,"ET MALWARE BTGrab.com Spyware Downloading Ads",1
```

---

### CEF (Common Event Format)
Uses **key-value pairs** structured into defined fields:

```
CEF:Version|Device Vendor|Device Product|Device Version|Signature ID|Name|Severity|Extension
```

- Fields separated by pipes `|`.
- The **Extension** field (optional) is written in key-value format.
- Often transported via Syslog, which prepends a timestamp and hostname.

Example:
```
Sep 29 08:26:10 host CEF:1|Security|threatmanager|1.0|100|worm successfully stopped|10|src=10.0.0.2 dst=2.1.2.2 spt=1232
```

| Field | Value |
|---|---|
| Syslog Timestamp | Sep 29 08:26:10 |
| Syslog Hostname | host |
| Version | CEF:1 |
| Device Vendor | Security |
| Device Product | threatmanager |
| Device Version | 1.0 |
| Signature ID | 100 |
| Name | worm successfully stopped |
| Severity | 10 |
| Extension | `src=10.0.0.2 dst=2.1.2.2 spt=1232` (optional) |

This entry describes a security app (**threatmanager**) that stopped a worm spreading from internal IP `10.0.0.2` to external IP `2.1.2.2` via port `1232`, with high severity (10).

## Key Terms

| Term | Definition |
|---|---|
| Log | A record of events occurring within an organization's systems |
| Log entry | A single record within a log detailing one event |
| Log analysis | The process of examining logs to identify events of interest |
| Verbose logging | Recording additional, detailed information beyond default logging |
| Log management | Process of collecting, storing, analysing, and disposing of log data |
| PII | Personally Identifiable Information  requires special handling in logs |
| Log retention | Policy for how long logs must be kept, often driven by regulation |
| FISMA | US regulation for public sector log/security requirements |
| HIPAA | US healthcare data protection regulation |
| PCI DSS / GLBA / SOX | Financial services regulations affecting log management |
| Centralized log server | Dedicated server storing logs away from local machines to preserve integrity |
| Log forwarder | Software that collects and forwards logs to a centralized repository |
| JSON | Lightweight key-value based data format using `{}` objects and `[]` arrays |
| Syslog | Logging protocol, service, and log format (header + structured-data + message) |
| Priority (PRI) | Syslog field indicating urgency  lower number = more urgent |
| XML | Tag/element/attribute-based data format, native to Windows |
| Root element | The top-level element in an XML document containing child elements |
| CSV | Format where data values are separated by commas, position-dependent |
| CEF | Common Event Format  pipe-separated fields with key-value extensions |
